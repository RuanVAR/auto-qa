📁
Project
Top-level container. Holds modules, environments, and run history. Connects to a source code repository for AI-assisted test generation.
🗂
Module
Maps to a logical area of your product — Authentication, Checkout, User Management. Analytics and pass rates are tracked per module.
✨
Feature
A specific user flow within a module. This is where the Test Player lives — run all test cases in a feature sequentially with one click.
🧪
Test Case
A single automated test. Can be type UI, API, or Shell. Steps are defined manually, generated by AI, or both. Fully exportable as JSON.

AI Layer

Your codebase teaches
the AI your app

Connect your repo. The AI reads your actual components, routes, and selectors — then generates tests that work first time.

🧠
Codebase-Aware Generation
Connect GitHub, GitLab, or a local path. The platform indexes your components and routes via RAG — the AI generates tests with real selectors from your actual code.
🔍
Failure Explanation
After every failed test, AI analyses the failed steps and tells you the root cause, failure category (UI/API/Auth/Timeout), suggested fix, and confidence level.
✍️
Auto Feedback per Test
In the Feature Player, AI automatically writes a short plain-English summary after each test case completes — no manual "explain" click needed.

Why PostgreSQL over MongoDB?
✓ Foreign keys + cascade deletes — enforces Project → Module → Feature → Test integrity at DB level
✓ ACID transactions — run state updates are atomic across multiple tables
✓ JSONB columns — steps, config, metadata stored as flexible JSON with index support
✓ pgvector — stores AI code embeddings for RAG test generation in the same DB
✓ SQL analytics — pass rates, trend data, flaky detection with simple GROUP BY queries
Run flow
POST /features/:id/run
↓ FeatureRunService.start()
↓ Creates TestRun records (PENDING)
↓ Enqueues first job → Redis
Worker picks up job
↓ Opens Playwright browser
↓ Executes steps sequentially
↓ Saves screenshots + trace
FeatureRunService.onRunComplete()
↓ Triggers AI feedback
↓ Emits WebSocket events
↓ Enqueues next test case
